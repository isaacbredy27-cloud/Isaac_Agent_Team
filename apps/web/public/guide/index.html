Follow the steps in order. Each step says what you will see when it works.

1. What the app is

Finance Match Orlando helps you find finance jobs in the Orlando area. You upload a resume. The app scores recent jobs against it and explains each score.

  • Your resume is read in memory and then deleted. It is never public.
  • Code works out the score. The same resume and job give the same score.
  • Admins can chat with project agents. Changes go live only after an admin taps Approve.

You can read more on the How it Works page.

2. Set up Supabase

Supabase handles sign in. You need a free Supabase account.

2a. Make a project

  1. Open the Supabase dashboard and pick New project.
  2. Name it. Choose a strong database password and save it in a password manager.
  3. Wait until the project says it is ready.
  4. Open Project Settings, then API Keys. Copy the Project URL and the publishable key. You will paste them into Netlify in step 3.

Never use the secret key. This app uses the publishable key only. See API keys.

2b. Run the migration

  1. In the repo, find the SQL file in the supabase/migrations folder. It makes the profiles table, the sign-up trigger and the row level security rules.
  2. In Supabase, open SQL Editor and pick New query.
  3. Paste the whole file. Select Run.
  4. Open Table Editor. You should see a profiles table.

Learn more: Row Level Security.

2c. Turn on the Google provider

  1. In Supabase, open Authentication, then Sign In / Providers, then Google.
  2. Copy the callback URL shown there. It looks like https://<project-ref>.supabase.co/auth/v1/callback.
  3. In Google Cloud, make an OAuth client of type Web application. Add that callback URL as an authorized redirect URI.
  4. Paste the Google client ID and client secret into the Supabase Google provider. Turn it on and save.

Google has rules for how the button looks. Read the branding guidelines. Full steps: Login with Google.

Keep it private. The Google client secret goes only in Supabase. Never put it in this repo or in Netlify.

2d. Add redirect URLs

  1. Open Authentication, then URL Configuration.
  2. Set Site URL to your live site, for example https://your-site.netlify.app.
  3. Under Redirect URLs, add your live site with a wildcard path, such as https://your-site.netlify.app/**.
  4. For local work, add http://localhost:8888/**.

Learn more: Redirect URLs.

2e. Make yourself super_admin

  1. Open the live app. Choose Create account or Continue with Google. Finish sign up and confirm your email.
  2. In Supabase, open SQL Editor. Run this, with your own email:
update public.profiles
set role = 'super_admin'
where id = (select id from auth.users where email = 'you@example.com');
  1. Open Table Editor, then profiles. Your row should show super_admin.

Check the column name. The migration file is the source of truth. If its column is not called role, use the name in the file.

2f. Enrol MFA

Admins must use an authenticator app. You do this once.

  1. Log in to the app. You will see Set up your authenticator app.
  2. Open an authenticator app on your phone. Scan the QR code. If you can't scan, type the text code.
  3. Enter the 6-digit code and select Verify and turn on.
  4. You will see Your authenticator is on. Select Continue.

Keep your phone safe. If you lose it, you must reset your factor in the Supabase dashboard. Learn more: Multi-factor authentication.

Make the GitHub token

  1. In GitHub, open Settings, Developer settings, Personal access tokens, then Fine-grained tokens.
  2. Choose Only select repositories. Pick this repo only.
  3. Under Repository permissions, set Contents to Read and write. Add nothing else.
  4. Set the expiry to 90 days. Copy the token once.
  5. In Netlify, add GITHUB_TOKEN for the Production context only. Never for Deploy Previews.

Put a reminder in your calendar for day 80. Learn more: fine-grained tokens.

Rule. Names that start with VITE_ reach the browser. Only the two Supabase values above use that prefix. Never give a secret that prefix.

4. Connect the repo and deploy

  1. In Netlify, choose Add new project, then Import an existing project.
  2. Pick GitHub and choose the Isaac_Agent_Team repo.
  3. Set the branch to main. Netlify reads the build settings from netlify.toml. The build command is npm run build. The publish folder is apps/web/dist.
  4. Add the variables from step 3. Select Deploy.
  5. When the deploy says Published, open the site. You should see the upload screen.
  6. Go back to Supabase step 2d and make sure your live URL is in the list.

Every push to main deploys again. The Free plan has 300 credits a month. Overage pauses every project, so check your usage each week. Learn more: Netlify Functions.

5. Use the app

  1. Upload. Open Resume. Choose a PDF or Word file up to 5 MB. You can paste text instead.
  2. Check. Fix any skill or title we guessed wrong.
  3. Browse. Open Jobs. Each job shows a score and a level: Strong, Moderate or Weak.
  4. Read why. Select a job. You see what matches, what is missing and what to do next.
  5. Close gaps. Open Gaps to see skills worth learning.
  6. Apply. Select Apply on the employer site. It opens in a new tab.

Your first match should show up in about a minute.

6. Use the Agents page and Approve

Only a super_admin with MFA sees the Agents tab.

  1. Log in. Enter your 6-digit code when asked.
  2. Open Agents. Pick an agent from the list.
  3. Type what you want. For example, ask the UX agent to improve a message.
  4. If the agent proposes a change, select Review proposal.
  5. Read the Why and the Changes. Green lines are added. Red lines are removed.
  6. Select Reject to throw it away. Nothing changes.
  7. Select Approve to save it. A sheet asks Confirm it's you. Enter your password and your 6-digit code. Select Confirm and approve.
  8. You will see Approved. Saved as and a short commit ID. Netlify deploys the change in a few minutes.

Good to know. Approve saves straight to main. If the code changed since the proposal, you see a message and nothing is saved. Ask the agent to update it. Use Undo this change to revert an approved change.
